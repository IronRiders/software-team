# Leadership

This folder contains documentation for all future Controls Directors. More than any other, this directory should be edited with every year on what went wrong, how it can be done better, and general information for posterity. Of course, this document is public to all software members.

If you're the Controls Director reading this, you may have noticed the distinct lack of how-to-be-a-software-lead documentation in our personal drive and the public Iron Riders drive. This new section of the software-team repo is meant to fix exactly that; this is a place to advise future Controls Directors, to document mistakes, and to pass down knowledge on software and project management in it.

# Season Logs

The [Season Logs](./season-logs) is a place to, at the end of each season, write down _everything_ that went wrong, why it did, and what can be done better. Additionally, please read all past season logs! There will never be any leadership improvement if we don't learn from the past.

It is mandatory for the Controls Director to do this each year!

# Curriculum

As Controls Director, it's your job to manage teaching rookies how to code on the robot. Remember that FRC, and this club, are not about the competition. The entire point is learning robotics- your job is to make sure that happens with everyone who wants it! Leads in the past have had no curriculum, or done all the programming themselves- which is problematic for a number of reasons- so make sure not to do that. It's also your responsibility to update curriculum each year in order to improve it and keep it up with the times.
