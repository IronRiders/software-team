# Season Log 2024-2025 Reefscape
Software Lead: mischa r. adler

### What went wrong?

* Curriculum was not comprehensive. Many things were not taught and had to be learned on-the-fly during the season. Curriculum did not finish/feel finished
* Rookie members were not assigned to real tasks (i.e. working on the actual robot) for very long/very often.
* Rookie members were often told that there was nothing for them to do due to their inexperience.
* People often didn't know where certain documents or resources were.
* During the mock season, software didn't end up testing any code.
* During mock and build season, rookies did not have enough opportunities to help and learn.
* Lack of project tracking and progress updates.
* Code made by rookies was often overwritten by experienced members. In itself, this is mostly okay. However, there was little reason _provided_ for doing so, meaning rookies could not learn from their mistakes because they were not told what those mistakes were.
* Many changes were made without notifying or consulting anyone. Additionally, several people made very large changes in order to institute their own design philosophy.
* Software guidelines were too loose, especially around branch management

### What went right?

* Curriculum was far better than the previous year (which had no curriculum)
* The software-team repository has been very helpful

### What can be done better?

* More involved (and fun) curriculum activities, including more opportunities to work on the full-scale robot rather than practice projects like the Romi.
* Curriculum also needs to include more general training such as electronics and how it relates to software.
* More in-depth Java lessons.
* A system for people to know what, when, and how they can work on the robot.
* Idea: use a 'flipped classroom' style, making people do Codecademy at home while practicing with fun activities during meetings.
* Use spreadsheets to keep track of individual students' progress and provide more individual help
* People should be told to/shown how to do more self-teaching (i.e. googling)
* Focus on robotics as a form of _learning_ rather than _competition_.
* Have a project that members build over the curriculum, so that at the end they can have something to be proud of
* System to track progress on code as well as weekly or even daily progress updates.
* More involved code review system where rookie code can be advised- via pull req reviews, ideally- and so overwriting is not necessary. This would also allow rookies to learn far more from mistakes/from other's advice.
* Software meetings with progress checks, help, etc. Communication with TODOs, announcement for _all_ software changes made to keep up with other software members and other departments. (I recommend a changelog channel on discord)
* Calendar with dates and timing goals for every task, maybe rewards when these tasks are complete.
* Integrating github issues with the discord bot to bring attention to it
